# Résumé — 11 Mai 2026

## 1. Cache OCR — Anti-doublon GPT-4o ‼️

- **Problème** : Si l'utilisateur uploade le même PDF deux fois → GPT-4o (Payant ~$0.01/page) appelé deux fois inutilement.
- **Solution implémentée** : Cache SHA-256 local (Package Python - Gratuit)
  - Nouveau fichier : `backend/app/core/ingestion/ocr_cache.py`
  - Modifié : `backend/app/core/ingestion/gpt4o_extractor.py`
  - Cache stocké dans : `backend/ocr_cache/ocr_results.json` (créé automatiquement)
- **Fonctionnement** :
  - 1ère insertion → GPT-4o appelé → résultat sauvegardé
  - ‼️ 2ème insertion même PDF → cache lu directement → **0$ dépensé**

---

## 2. Erreur encodage nom de fichier arabe ‼️

- **Problème** : PDF avec nom arabe (`مدونة_السير...`) → corrompu en `?????` sur Windows → fichier introuvable → statut `error`
- **Cause** : `safe_filename` inclus dans le chemin physique du fichier
- **Solution** : Sauvegarde du PDF avec **UUID uniquement** comme nom sur disque (`{uuid}.pdf`)
  - Modifié : `backend/app/api/routes/documents.py` ligne 137
  - Le nom arabe est conservé **uniquement pour l'affichage** dans le registre

---

## 3. LLM répondait "لم أجد معلومات كافية" malgré sources à 99% ‼️

- **Problème** : Le modèle Qwen2.5 (Logiciel installé depuis site web - Gratuit) refusait de répondre
- **Causes** :
  - `num_ctx: 2048` → contexte trop petit pour le texte arabe dense
  - `num_predict: 512` → réponse trop courte
  - Prompt trop strict → le modèle préférait dire "pas assez d'infos"
  - Seulement 3 chunks fournis au LLM
- **Corrections dans** `backend/app/core/generation/llm.py` :
  - `num_ctx` : 2048 → **4096**
  - `num_predict` : 512 → **1024**
  - Chunks : 3 → **5**
  - Prompt : assoupli (répondre même si info partielle)
- **Résultat** : ✅ Réponse correcte obtenue — "الإجابة هي 14 سنة خمسية كاملة"
